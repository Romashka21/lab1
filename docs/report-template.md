## 2. Змінений маршрут
Реалізовано наскрізний маршрут `GET /api/incidents/severity-summary`.
*Детальне трасування маршруту від кнопки у браузері до SQL-запиту в PostgreSQL наведено у повному PDF-звіті.*

## 3. Виконані зміни
Додано спеціалізований DTO, реалізовано запит через EF Core з використанням `GroupBy` та політики нульових груп, підключено endpoint та створено безпечний UI-обробник для уникнення XSS.
*Фрагменти коду та опис логіки див. у PDF-звіті.*

## 4. Перевірка
Усі передбачені тест-кейси (T-01 – T-08) пройдено успішно, включаючи додаткові перевірки для доброго рівня.
*Повну матрицю перевірки з доказами та скриншотами (DevTools Network, статуси 200/404/400, результати автоматизованих тестів `dotnet test`) наведено у PDF-звіті.*

## 5. Security-сценарій
Виправлено небезпечне використання властивості `innerHTML` у клієнтському скрипті (app.js) на безпечну альтернативу `textContent` для захисту від XSS-ін'єкцій. 
*Опис вразливості, локальний PoC та результати виправлення містяться у PDF-звіті.*

## 6. Висновок
Лабораторну роботу №1 виконано в повному обсязі. Точку розширення API успішно реалізовано з дотриманням контракту. Код відповідає вимогам безпеки (успішно проходить тест на відсутність небезпечних DOM-приймачів). Автоматизовані перевірки та HTTP-сценарії виконуються без помилок.
